Como Atualizar a AWS ao Dar `git push`

Automatize deploys em produção para que cada alteração commitada no GitHub atualize a AWS sem trabalho manual.

💻 Você
git push origin main
➔
🐙 GitHub
Repositório detecta novo commit
➔
⚡ GitHub Actions / App Runner
Executa build automático
➔
☁️ AWS Produção
S3/CloudFront & App Runner atualizados!
1 Como funciona para o Backend FastAPI (AWS App Runner)

O AWS App Runner possui integração **nativa com o GitHub**:

  • Na aba de configurações do App Runner, ative a opção Automatic Deployment: Automatic.
  • Sempre que você der git push origin main, o App Runner puxa o código novo, reconstrói o `Dockerfile` e atualiza a API em produção **sem derrubar o sistema** (*zero-downtime deployment*).
2 Como funciona para o Frontend TypeScript (GitHub Actions + S3)

Para o Frontend, crie um arquivo no seu projeto em .github/workflows/deploy-frontend.yml:

name: Deploy Frontend para AWS

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout do código
        uses: actions/checkout@v4

      - name: Instalar Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Instalar dependências e fazer Build
        run: |
          cd frontend
          npm ci
          npm run build

      - name: Configurar Credenciais AWS
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: us-east-1

      - name: Sincronizar pasta dist com Amazon S3
        run: aws s3 sync frontend/dist/ s3://meu-bucket-frontend --delete

      - name: Limpar Cache do CloudFront (Invalidation)
        run: aws cloudfront create-invalidation --distribution-id SEU_DISTRIBUTION_ID --paths "/*"
3 E se houver alterações na Estrutura do Banco de Dados? (Migrations Alembic)

Se a sua alteração no código incluir novos campos ou tabelas no PostgreSQL (novas migrations no Alembic):

  1. Você roda a migration antes no banco de staging ou adiciona o comando alembic upgrade head na inicialização da sua API no `Dockerfile`.
  2. Assim, quando o novo contêiner subir na AWS, ele executa as migrations automaticamente antes de aceitar conexões dos usuários!

🧠 Teste de Fixação

Por que enviamos o comando aws cloudfront create-invalidation após enviar os arquivos estáticos novos para o S3?

A) Para deletar o banco de dados e recriá-lo.
B) Para forçar o CloudFront a apagar a cópia antiga em cache e entregar imediatamente o novo JavaScript/CSS compilado para os usuários.
C) Para desligar o servidor durante a manutenção.
